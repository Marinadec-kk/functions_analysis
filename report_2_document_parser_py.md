# Отчет по скрипту: pipeline/document_parser.py

## 1. Общее назначение

Этот скрипт является **модульным компонентом** более крупного пайплайна обработки данных. Его основная задача — автоматическое извлечение структурированной информации из юридических документов (`.docx` и `.doc`).

Скрипт выполняет следующие шаги:
1.  Рекурсивно находит все документы в указанной папке.
2.  Читает содержимое документов, при необходимости конвертируя `.doc` в `.docx`.
3.  С помощью AI-модели извлекает полное наименование государственного органа.
4.  Парсит иерархию ведомств (основное и вышестоящее).
5.  Находит и извлекает список функций госоргана.
6.  Формирует и сохраняет итоговые данные в виде единого Excel-файла.

## 2. Архитектура и структура

- **Модульная архитектура**: Скрипт спроектирован как независимый, переиспользуемый модуль. Вся логика разделена на небольшие, четко определенные функции.
- **Конфигурация через объект**: Управляется через единый словарь `config`, что позволяет легко настраивать параметры (пути, модели AI, промпты) извне, не изменяя код.
- **Отсутствие GUI**: Скрипт предназначен для выполнения в командной строке или для вызова из других Python-модулей. Для индикации прогресса используется библиотека `tqdm`.
- **Кроссплатформенность**: Для конвертации `.doc` в `.docx` используется внешняя утилита **LibreOffice** в headless-режиме. Это делает скрипт совместимым с различными ОС (Linux, macOS, Windows), где может быть установлен LibreOffice.
- **Структурированное логирование**: Активно используется стандартная библиотека `logging` для записи информационных сообщений, предупреждений и ошибок, что упрощает отладку.

## 3. Ключевые функции и логика работы

### 3.1. Основной поток выполнения (`run_document_parser`)

Это главная функция, которая координирует весь процесс:

1.  **Настройка**: Инициализирует логирование (`setup_logging`) и загружает текст промпта из файла (`load_prompt`).
2.  **Поиск документов (`find_documents`)**: Рекурсивно сканирует входную директорию и составляет список всех `.doc` и `.docx` файлов, игнорируя временные файлы (например, начинающиеся с `~$`).
3.  **Итеративная обработка**: Проходит по списку найденных документов в цикле с `tqdm` и для каждого вызывает `process_document`.
4.  **Агрегация результатов**: Собирает все результаты обработки в один список.
5.  **Сохранение в Excel**: Создает `pandas.DataFrame` из списка результатов и сохраняет его в `.xlsx` файл.

### 3.2. Обработка одного файла (`process_document`)

1.  **Чтение документа (`read_document_paragraphs`)**:
    - Если файл `.docx`, он читается с помощью `python-docx`.
    - Если файл `.doc`, он сначала **конвертируется в `.docx`** с помощью системной команды `libreoffice` (или `soffice`). Конвертация происходит во временной директории, которая затем удаляется. Этот подход более надежен и универсален, чем `win32com`.
2.  **Извлечение наименования госоргана (`extract_government_body_name`)**:
    - Аналогично старому скрипту, использует AI-модель для извлечения названия из первых 150 параграфов. Процесс включает обработку ошибок API и повторные попытки.
    - Использует более современный `httpx` клиент для HTTP-запросов.
3.  **Парсинг иерархии (`parse_government_hierarchy`)**:
    - Выделена в отдельную, чистую функцию. Принимает полное наименование и на основе ключевых слов (`Министерства`, `Агентства` и т.д.) разделяет его на `main_go` и `parent_go`.
4.  **Извлечение функций (`extract_functions`)**:
    - Ищет заголовок "Функции" (с учетом вариаций). После нахождения считывает все последующие непустые параграфы до следующего крупного раздела ("Глава", "Раздел").
    - Возвращает кортеж из списка функций и статуса (`OK`, `HEADER_NOT_FOUND`, `NO_ITEMS_FOUND`), что делает обработку ошибок более явной.
5.  **Очистка текста (`clean_function_text`)**:
    - Отдельная функция для очистки текста каждой функции от мусорных конструкций с помощью набора регулярных выражений.
6.  **Создание аббревиатуры (`create_government_abbreviation`)**:
    - Генерирует аббревиатуру из названия госоргана.

## 4. Преимущества и улучшения

- **Модульность и переиспользуемость**: Легко интегрируется в другие системы. Функции независимы и могут быть использованы отдельно.
- **Кроссплатформенность**: Благодаря использованию LibreOffice скрипт не привязан к Windows.
- **Надежность**: Улучшенная обработка ошибок, использование `try-except`, явные статусы возврата и структурированное логирование.
- **Читаемость и поддержка**: Код хорошо структурирован, использует аннотации типов, разделен на логические блоки, что упрощает его понимание и доработку.
- **Гибкость**: Вся конфигурация вынесена во внешний объект, что позволяет легко адаптировать пайплайн под разные задачи.
- **Современный стек**: Используются актуальные библиотеки, такие как `pandas` для работы с данными и `httpx` для сетевых запросов.
