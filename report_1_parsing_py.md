# Отчет по скрипту: pre_ref/1_parsing.py

## 1. Общее назначение

Этот скрипт представляет собой **монолитное десктопное приложение с графическим интерфейсом (GUI)**, созданное с использованием библиотеки `tkinter`. Основная задача приложения — пакетная обработка документов `.doc` и `.docx` из указанной пользователем папки для извлечения наименований государственных органов и списка их функций.

Скрипт объединяет в себе логику пользовательского интерфейса, обработку файлов, взаимодействие с AI-моделью и сохранение результатов.

## 2. Архитектура и структура

- **Монолитная архитектура**: Вся функциональность заключена в одном файле.
- **Класс `ParserApp`**: Является центральным элементом, который инкапсулирует всю логику приложения:
    - Создание и управление GUI.
    - Обработка пользовательских событий (нажатие кнопок "Старт", "Стоп").
    - Управление конфигурацией (получение API-ключей, выбор режима AI).
    - Запуск и координация фоновых потоков для обработки файлов, чтобы не блокировать интерфейс.
- **Графический интерфейс**: Построен на `tkinter` и включает в себя:
    - Поля для ввода папок (входной и выходной).
    - Поля для ввода API-ключа и URL сервера.
    - Переключатель режима работы AI ("Онлайн", "Локальный", "АП").
    - Кнопки для запуска и остановки процесса.
    - Текстовое поле для вывода логов и статуса выполнения.

## 3. Ключевые функции и логика работы

### 3.1. Основной поток выполнения (`_master_thread_logic`)

1.  **Получение конфигурации**: Считывает все настройки из полей GUI (`_get_config`).
2.  **Поиск документов**: Находит все файлы `.doc` и `.docx` в указанной входной папке.
3.  **Параллельная обработка**: Запускает несколько рабочих потоков (`_file_processor_worker`) для одновременной обработки файлов. Количество потоков ограничено (по умолчанию 5).
4.  **Сбор результатов**: Собирает результаты обработки от каждого потока.
5.  **Генерация отчетов**: После завершения обработки всех файлов создает два отчета:
    - **Статистический отчет** (`_generate_stats_report`): Сводка по количеству обработанных файлов, найденных функций и ошибкам.
    - **Основной отчет** (`_save_report`): Сохраняет извлеченные данные в формате `.xlsx`.

### 3.2. Обработка одного файла (`_process_single_file`)

Это ядро всей логики извлечения данных:

1.  **Чтение документа**:
    - Для `.docx` используется библиотека `docx`.
    - Для `.doc` используется специфичная для Windows библиотека `win32com` (`read_doc_paragraphs_win32`), что делает скрипт **не кроссплатформенным**.
2.  **Извлечение наименования госоргана (`_extract_full_go_name`)**:
    - Первые 150 параграфов документа отправляются в AI-модель (OpenAI API).
    - Скрипт использует специальный промпт для получения полного наименования госоргана в формате JSON.
    - Включает логику повторных попыток при ошибках API.
3.  **Разбор иерархии (`_parse_full_go_name`)**:
    - После получения полного наименования, функция пытается определить основное и вышестоящее ведомство на основе ключевых слов (например, "Министерства", "Агентства").
4.  **Извлечение функций (`enumerate_functions`)**:
    - Скрипт ищет в тексте заголовок "Функции".
    - После нахождения заголовка, он считывает последующие параграфы как отдельные функции, пока не встретит следующий раздел (например, "Глава X").
5.  **Очистка текста (`fast_clean_and_format_text`)**:
    - Удаляет из текста функций "мусорные" элементы: сноски, примечания, информацию о введении в действие, номера пунктов и т.д. с помощью регулярных выражений.
6.  **Создание аббревиатуры (`create_abbreviation`)**:
    - Генерирует короткую аббревиатуру из названия госоргана для использования в ID функции.

## 4. Особенности и недостатки

- **Зависимость от Windows**: Использование `win32com` для чтения `.doc` файлов ограничивает работу скрипта только этой ОС.
- **Монолитность**: Смешивание GUI, логики обработки и взаимодействия с API в одном файле затрудняет поддержку и повторное использование кода.
- **Отсутствие типизации и логирования**: В коде отсутствуют современные практики, такие как аннотации типов и структурированное логирование, что снижает его читаемость и надежность.
- **Жесткая структура**: Логика жестко привязана к структуре GUI. Ее сложно использовать как отдельный модуль в других системах.
