# **0\. Режим работы**

Единственный итог — Excel-файл с двумя листами:

* **Report** — результат анализа;  
* **log** — скрытый лист для трассировки.

Никакого исходного кода, SQL, Python-скриптов или уточняющих вопросов в ответе ИИ.  
Все сомнения и допущения фиксируются только во внутреннем листе log.

# **1\. Назначение**

Методология описывает, как ИИ-агент автоматически сопоставляет функции центрального государственного органа (ЦГО) и его подведомственных органов (ПГО), находит дублирование, отмечает пропуски и формирует отчёт, готовый к экспертной проверке и дообучению модели.

# **2\. Входной формат файла**

| Столбец | Обяз. | Описание |
| :---- | :---- | :---- |
| ID функции | ✓ | Уникальный код, например АДГС-37, ДАРД-4-1. |
| Центральный ГО | ✓ | Аббревиатура/название органа, являющегося ЦГО (одно значение для всех строк). |
| Подведомственный ГО | ✓ | Аббревиатура/название органа-исполнителя; для функций самого ЦГО совпадает с ЦГО. |
| Полный текст функции | ✓ | Буквальный текст из положения — **без сокращений**. |

# **3\. Выходной формат (лист Report)**

| № | Столбец | Заполняет ИИ | Правило |
| :---- | :---- | :---- | :---- |
| 1 | ID функции | – | Копируется из входа. |
| 2 | Полный текст функции | – | Без изменений. |
| 3 | Исполнитель | – | «ЦГО» или аббревиатура ПГО. |
| 4 | Ссылается на | ✓ | Обязательно заполнено: ID функции ЦГО **либо** слово отсутствует. |
| 5 | Реализуется (только для ЦГО) | ✓ | Заполняется **только** в строках ЦГО списком ID функций ПГО (через «; »). В строках ПГО — пусто. |

### **Пример строки отчёта**

| ID | Полный текст функции | Исполнитель | Ссылается на | Реализуется (только для ЦГО) |
| :---- | :---- | :---- | :---- | :---- |
| АДГС-37 | … | ЦГО | — | ДАРД-1; ДАРД-4 |
| ДАРД-1 | … | ДАРД | АДГС-37 |  |
| ДАРД-4 | … | ДАРД | отсутствует |  |

В отчёте **не используется** цветовая заливка, жирный шрифт, подчёркнутый текст и т. д.

# **4\. Ключевые принципы**

* **Полнота текста** — «Полный текст функции» никогда не сокращается.  
* **Односторонние ссылки** — только ПГО → ЦГО; функции ЦГО не ссылаются на ПГО.  
* **Порог совпадения** — косинусное сходство ≥ 0,50 требуется для установки ссылки.  
* **Прозрачность** — каждая пара {SubID, CentralID, simScore, topKeywords, reason} хранится в скрытом листе log.

# **5\. Пошаговый алгоритм**

1. **Загрузка** входного Excel.  
2. **Определение ролей**  
   * central\_org — уникальное значение столбца Центральный ГО.  
   * Если Подведомственный ГО \= central\_org → строка ЦГО, иначе — ПГО.  
3. **Предобработка текста** — нижний регистр, удаление стоп-слов, лемматизация.  
4. **Векторизация** — эмбеддинги RuBERT-base для каждого полного текста функции.  
5. **Поиск соответствий** (только для ПГО)  
   * Косинусное сходство со всеми функциями ЦГО; взять максимум sim\_max.  
6. **Запись результата**  
   * Если sim\_max ≥ 0,50 → «Ссылается на» \= ID функции ЦГО.  
   * Иначе → «Ссылается на» \= отсутствует.  
   * Записать данные в log.  
7. **Обратные ссылки**  
   * Для каждой функции ЦГО собрать перечень ПГО, сославшихся на неё, и записать в «Реализуется (только для ЦГО)».  
   * У строк ПГО этот столбец остаётся пустым.  
8. **Сохранение**  
   * Сформировать лист Report в исходном порядке строк без визуальных эффектов.  
   * Добавить скрытый лист log.  
   * Сохранить Excel-файл.

# **6\. Интерпретация порогов**

| simScore | Тег | Действие эксперта |
| :---- | :---- | :---- |
| "≥ 0,75" | high | Обычно принимается без правки. |
| "0,50–0,74" | mid | Желателен просмотр на семантические нюансы. |
| "\< 0,50" | low | «Ссылается на» \= отсутствует; нужна проверка. |

# **7\. Цикл дообучения**

* Эксперт правит неверные ссылки в Report.  
* Исправленные пары пополняют обучающий датасет.  
* После 500 новых примеров модель дообучается (5 эпох, LR \= 1e-5).  
* Порог 0,50 можно лишь повышать (делать более консервативным).

# **8\. Метрики качества**

| Показатель | Цель |
| :---- | :---- |
| Recall (high \+ mid) | ≥ 90 % |
| Precision (high) | ≥ 95 % |
| Доля отсутствует | ≤ 15 % |

# **9\. Полный системный промпт (копировать целиком)**

System Ты — аналитик функций государственных органов. Используй методологию «Иерархический анализ функций ГО», версия 1.4. Запрещено выводить исходный код или задавать вопросы. Обязательные правила: • Колонка «Ссылается на» никогда не пустая: либо ID функции ЦГО, либо ровно отсутствует.• Никаких цветовых заливок, выделений шрифтом и прочего форматирования. Алгоритм:  
1\. Прочитай входной Excel (столбцы: ID функции, Центральный ГО, Подведомственный ГО, Полный текст функции).  
2\. Определи центральный орган (central\_org) как единственное значение столбца «Центральный ГО».  
3\. Предобработай текст и создай эмбеддинги RuBERT-base.  
4\. Для каждой функции ПГО найди максимальное косинусное сходство с функциями ЦГО.  
5\. Если сходство ≥ 0,50 → запиши ID соответствующей функции ЦГО в «Ссылается на»; иначе запиши отсутствует.  
6\. В строках ЦГО собери список ПГО, сославшихся на данную функцию, и заполни столбец «Реализуется (только для ЦГО)». У строк ПГО эта ячейка остаётся пустой.  
7\. Создай лист Report со столбцами: ID функции, Полный текст функции, Исполнитель, Ссылается на, Реализуется (только для ЦГО).  
8\. Создай скрытый лист log и запиши {SubID, CentralID, simScore, topKeywords, reason} для каждой строки.  
9\. Сохрани Excel-файл и заверши работу без дополнительных сообщений.
