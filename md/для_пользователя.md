# **Объяснение работы скрипта анализа иерархии функций**

Этот документ простыми словами описывает, как работает автоматический анализ функций государственных органов.

### **1. Какую задачу решает скрипт?**

Представьте себе структуру государственных органов как дерево, где есть "ветки-родители" и "ветки-дети". У каждой "ветки" (органа) есть свои функции.

**Задача скрипта** — автоматически построить связи в этом дереве. Он определяет, какие функции являются "дочерними" по отношению к более общим, "родительским" функциям. Это помогает понять, как задачи спускаются "сверху вниз", найти дублирование и увидеть, где в иерархии есть пробелы.

### **2. Что нужно для начала работы?**

Скрипту требуется один Excel-файл, в котором есть пять обязательных колонок:

1.  **ID**: Уникальный код для каждой функции (например, `МВД-123` или `МВД-123-1`).
2.  **Вышестоящий ГО**: Название органа, который является "родителем" для текущей функции.
3.  **Исполняющий ГО**: Название ведомства, которое непосредственно выполняет функцию.
4.  **Level**: Цифра, обозначающая уровень функции в иерархии. Чем больше цифра, тем ниже функция в "дереве" (например, функция 2-го уровня подчиняется функции 1-го уровня).
5.  **FunctionText**: Самое подробное и официальное описание того, что делает функция.

**Ключевой принцип**: Функция "ребенок" (например, `Level 2`) находит своего "родителя" (`Level 1`) по связке названий органов: `Вышестоящий ГО` ребенка должен совпадать с `Исполняющий ГО` родителя.

### **3. Как происходит анализ? (По шагам)**

1.  **Загрузка и сортировка**: Скрипт читает ваш Excel-файл и выстраивает все функции по порядку — от самого верхнего уровня (`Level 1`) к самому нижнему. Тексты функций очищаются от "мусора" (лишние слова, знаки препинания), чтобы машине было проще их сравнивать.

2.  **"Перевод" на язык чисел**: Каждая функция "переводится" в набор чисел (вектор). Это позволяет математически сравнить, насколько тексты функций похожи друг на друга по смыслу.

3.  **Поиск связей "Ребенок-Родитель"**: Скрипт берет каждую "дочернюю" функцию (например, с `Level 2`) и ищет для нее подходящего "родителя" на уровне выше (`Level 1`). Поиск идет не по всем функциям подряд, а только среди тех, у кого совпадают названия органов (см. "Ключевой принцип" выше).

4.  **Принятие решения**:
    *   Среди найденных потенциальных "родителей" скрипт выбирает того, чья функция по смыслу наиболее похожа на функцию "ребенка".
    *   Если сходство больше 50%, скрипт устанавливает между ними связь.
    *   Если достаточно похожей функции не нашлось, скрипт делает пометку, что связь «отсутствует».

5.  **Сборка обратных связей**: После того как все связи "детей" к "родителям" установлены, скрипт возвращается к "родительским" функциям. Для каждой из них он составляет список всех "детей", которые на нее ссылаются.

### **4. Что получается в итоге?**

Результатом работы являются **два новых Excel-файла**:

1.  **Таблица №1 `TABLES_S_ORIGINALNAME+hierarchy.xlsx` (Отчет)**
    Это главная таблица с результатами. В ней сохраняются **все ваши изначальные колонки**, к которым добавляются два новых столбца:
    *   **`Ссылается на`**: Для "дочерних" функций здесь будет указан ID той "родительской" функции, которую она исполняет. Если связь не найдена, будет написано слово `отсутствует`.
    *   **`Реализуется (только для ЦГО)`**: Эта колонка заполняется только для "родительских" функций. В ней будет список ID всех "дочерних" функций, которые ее исполняют.

2.  **Таблица №2 `log.xlsx` (Технический лог)**
    Это подробная таблица для специалистов. Она включает в себя **все колонки из первого отчета**, а также **дополнительные столбцы** с техническими деталями: например, точный процент смыслового сходства (`simScore`) для каждой пары функций. Это помогает детально проверить, почему алгоритм принял то или иное решение.
