# Обзор скрипта `scripts/4_group+dub.py`

## Назначение
- Настольное приложение на Tkinter ищет дублирующие («коллизирующие») функции разных госорганов, опираясь на эмбеддинги и последующую AI-верификацию.
- Версия 14.3 реализует перераспределение нагрузки: для каждого локального сервера создаётся собственный пул воркеров, что убирает конкуренцию и непредсказуемые задержки.
- Полностью автоматизирует цикл: загрузка файла, группировка по выбранным столбцам, поиск кандидатов, проверка LLM и выгрузка отчёта с пометками о коллизиях.

## Входные данные и настройки
- Пользователь указывает исходный Excel/CSV, каталог для выгрузки и (опционально) JSON с «универсальными» функциями, которые нужно исключать из анализа.
- Столбцы группировки выбираются через двойной список: слева доступные поля из загруженного файла, справа — активные (по умолчанию `Type`, `Sphere_3`).
- Порог похожести, порог для универсальных функций, параметры эмбеддингов (сервер, модель, число воркеров, размер batch) задаются на втором шаге.
- AI-верификация включается отдельным чекбоксом: режим «Онлайн» требует API-ключ и модель OpenAI, режим «Локальная» — список адресов LM Studio и имя модели; общие параметры включают температуру, лимит токенов и JSON-ответ (для онлайн).

## Подготовка и фильтрация
- При запуске проверяется валидность путей, существование выбранных столбцов и создаётся папка результатов.
- Таблица приводится к строковым ID; по группам, определённым пользователем, формируются поднаборы данных.
- Если в группе присутствует метка `Type == "Общие функции"`, такие строки исключаются — анализ ведётся только по специализированным действиям.
- JSON универсальных функций рекурсивно обходится, из него извлекаются тексты и векторизуются, чтобы в дальнейшем отфильтровать слишком общие записи по отдельному порогу сходства.

## Расчёт эмбеддингов
- Для каждой группы формируются батчи текстов и отправляются на указанный сервер эмбеддингов через клиента OpenAI-совместимого API.
- Многопоточный пул воркеров (число задаётся пользователем) берёт задания из очереди, повторяя попытки запроса до трёх раз и записывая успешные эмбеддинги в общую структуру под блокировкой.
- Нормализация и косинусные матрицы считаются в torch; вычисления ведутся на CPU, но пригодны и для GPU при соответствующей установке.

## Поиск кандидатов
- Внутри каждой группы сравниваются только те строки, что не признаны «универсальными» (по косинусному сходству с готовыми эталонами ≥ заданного порога).
- Пары формируются для разных исполнителей (`Исполняющий ГО`) и только один раз (верхний треугольник матрицы), что исключает самоповторы.
- Идентификаторы пар стандартизируются (строковый формат, сортировка) и накапливаются в множестве, чтобы убрать дубликаты между группами.
- Прогресс по группам отображается отдельной полосой с оценкой времени (ETR) и счётчиком найденных кандидатов.

## AI-верификация
- Если этап включён, каждая пара отправляется в LLM с подробным системным промптом, требующим JSON-ответа `{"verdict": "CORRECT|NOT_CORRECT"}`.
- Онлайн-режим создаёт одного клиента OpenAI и порождает заданное число потоков; локальный режим строит по `WORKERS_PER_LOCAL_SERVER` потоков на каждый сервер, что равномерно распределяет нагрузку (нововведение 14.3).
- Ответы проходят до трёх повторных запросов; предусмотрена обработка ошибок аутентификации, статуса, сетевых сбоев и превышения квот. При фатальном сбое все кандидаты автоматически считаются подтверждёнными, чтобы не потерять сигнал.
- Подтверждённые коллизии фиксируются в защищённом множестве через блокировку, а прогресс отображается на второй полосе.

## Контроль качества и устойчивость
- Кнопка «Стоп» ставит флаг, который регулярно проверяют все рабочие потоки (эмбеддинги, AI, основная нить) и завершают работу корректно.
- Обновление интерфейса вынесено в потокобезопасную очередь: сообщения, статус, прогресс и счётчик кандидатов синхронизируются с главным Tk-интерфейсом.
- Ошибки чтения JSON, отсутствие колонок, проблемы API и недоступность серверов логируются в UI и, при необходимости, выводятся в консоль.
- Перед сохранением добавляются/очищаются технические столбцы `Anomaly`, `CollisionWith`, что предотвращает KeyError при повторных пусках.

## Интерфейс и рабочий процесс
- Левая панель — три пошаговых блока настроек (данные/группировка, эмбеддинги, AI) с интуитивными элементами выбора файлов и списками колонок.
- Правая панель содержит управление запуском, две независимые полосы прогресса (поиск и проверка) с ETR и счётчиком кандидатов, редактор системного промпта и журнал действий.
- Таймер внизу отслеживает длительность сессии; статусная строка показывает текущую группу или этап.
- Приложение применяет тему `sv_ttk`, если доступна, иначе работает на стандартном оформлении.

## Итоговые файлы
- Результирующий Excel `Сводный_отчет_по_коллизиям_<YYYYMMDD_HHMMSS>.xlsx` сохраняется в выбранной папке и наследует все исходные колонки, дополняясь полями `Anomaly` и `CollisionWith` с перечнем найденных коллизий.
- Отдельного технического лога не создаётся; информация о ходе выполнения остаётся в UI-журнале с возможностью копирования.

## Бизнес-смысл
- Решение позволяет быстро выявлять дублирование функций между ведомствами в рамках заданной предметной области, снижая затраты аналитиков на ручное сопоставление.
- Отсечение общих/универсальных формулировок и двухэтапная проверка (эмбеддинги + LLM) повышают точность, а новые механизмы распределения нагрузки делают анализ масштабируемым на парк локальных серверов.
- Настраиваемые пороги и промпт дают экспертам контроль над точностью/полнотой, а единый Excel-отчёт упрощает передачу результатов заинтересованным сторонам.
