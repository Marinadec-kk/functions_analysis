# Запрос на рефакторинг и создание модульной структуры проекта

## 1. Общая цель

Провести рефакторинг набора Python-скриптов, предназначенных для анализа текстовых данных. Основная задача — перейти от монолитных скриптов, где логика и пользовательский интерфейс тесно связаны, к модульной архитектуре. Это повысит переиспользуемость кода, упростит его поддержку и дальнейшее развитие.

Новый реструктурированный проект должен быть сохранен в директорию `./refactor`.

## 2. Ключевое требование: Сохранение GUI

**КРИТИЧЕСКИ ВАЖНО:** Внешний вид и функциональность пользовательских интерфейсов (GUI) каждого из оригинальных скриптов должны быть сохранены в неизменном виде. Все окна, кнопки, поля ввода, вкладки и другие элементы управления должны выглядеть и работать так же, как в исходных версиях.

Все изменения должны касаться исключительно внутренней структуры кода ("бэкенда"), отделяя логику от ее графического представления.

## 3. Предлагаемая модульная структура

Необходимо разбить код на следующие логические модули в рамках новой директории `refactor`:

### 3.1. `refactor/core/` — Ядро приложения

Эта директория должна содержать всю бизнес-логику, не зависящую от GUI.

-   **`core/file_io.py`**: Модуль для всех операций с файлами.
    -   **Обязанности:** Чтение и запись файлов различных форматов (`.xlsx`, `.json`, `.txt`, `.csv`).
    -   **Примеры функций для переноса:** `read_doc_paragraphs_win32`, `read_table_auto`, `load_df`, `save_report`, `save_file`.

-   **`core/text_processing.py`**: Модуль для обработки и нормализации текста.
    -   **Обязанности:** Очистка текста, удаление стоп-слов, лемматизация, создание аббревиатур.
    -   **Примеры функций для переноса:** `fast_clean_and_format_text`, `create_abbreviation`, `normalize_name_key`, `TextNormalizer`.

-   **`core/ai/`**: Пакет для взаимодействия с моделями искусственного интеллекта.
    -   **`ai/client.py`**: Унифицированный клиент для работы с API нейронных сетей и локальными моделями. Должен поддерживать разные режимы (`local`, `remote`, `azure`, etc.) и обрабатывать логику повторных запросов (`backoff`).
    -   **`ai/embedding.py`**: Функции для получения векторных представлений (эмбеддингов) текста. Примеры: `async_get_embeddings`, `get_embedding_from_server`, `RuBertEmbedder`.
    -   **`ai/classification.py`**: Функции, использующие LLM для классификации, верификации и принятия решений. Примеры: `_get_llm_verdict`, `call_ai_1_for_classification`.
    -   **`ai/prompts.py`**: Хранилище для всех системных промптов, используемых в проекте.

-   **`core/analysis/`**: Пакет с основной логикой каждого из аналитических инструментов.
    -   **`analysis/parsing.py`**: Логика из `1_parsing.py` (извлечение функций из документов).
    -   **`analysis/typing.py`**: Логика из `2_types.py` (типология функций).
    -   **`analysis/spheres.py`**: Логика из `3_spheres.py` (классификация по сферам).
    -   **`analysis/grouping.py`**: Логика из `4_group+dub.py` (группировка и поиск коллизий).
    -   **`analysis/duplicate_checking.py`**: Логика из `5_dublicates_check.py`.
    -   **`analysis/hierarchy.py`**: Основная логика из `hierarchy/hierarchy_gui.py` (класс `HierarchyAnalyzer`).
    -   **`analysis/reporting.py`**: Логика из `6_md_sharding.py` (генерация `.md` отчетов).

### 3.2. `refactor/gui/` — Пользовательский интерфейс

Эта директория должна содержать весь код, связанный с построением и управлением GUI на базе Tkinter.

-   **`gui/app_base.py`**: Базовый класс для всех приложений.
    -   **Обязанности:** Управление жизненным циклом приложения, обработка фоновых задач (worker threads), управление очередью UI-событий (`_drain_ui_queue`), логирование в GUI.

-   **`gui/widgets.py`**: Набор переиспользуемых виджетов.
    -   **Обязанности:** Создание стандартных элементов интерфейса, таких как строки для выбора файлов (`_create_file_row`), поля ввода (`_create_entry_row`), селекторы режима AI.

-   **`gui/parser_app.py`**: GUI для скрипта `1_parsing.py`.
-   **`gui/typing_app.py`**: GUI для скрипта `2_types.py`.
-   **`gui/spheres_app.py`**: GUI для скрипта `3_spheres.py`.
-   **`gui/grouping_app.py`**: GUI для скрипта `4_group+dub.py`.
-   **`gui/duplicate_checking_app.py`**: GUI для скрипта `5_dublicates_check.py`.
-   **`gui/hierarchy_app.py`**: GUI для скрипта `hierarchy/hierarchy_gui.py`.
-   **`gui/sharding_app.py`**: GUI для скрипта `6_md_sharding.py`.

Каждый `*_app.py` файл должен импортировать и использовать соответствующий модуль логики из `refactor/core/analysis/`.

### 3.3. `refactor/config/` — Конфигурация

-   **`config/settings.py`**: Модуль для управления глобальными настройками (например, путями к файлам по умолчанию, параметрами API).
-   **`config/profiles/`**: Директория для хранения профилей настроек пользователя (как в `hierarchy_gui.py`).

### 3.4. `refactor/main.py` — Точка входа

-   **Обязанности:** Предоставить пользователю возможность выбора и запуска любого из доступных инструментов (GUI-приложений). Это может быть простое консольное меню или главное окно с кнопками для каждого из приложений.

## 4. План выполнения

1.  Создать новую структуру директорий внутри папки `refactor`.
2.  Перенести и адаптировать код из существующих скриптов в новые модули в соответствии со структурой, описанной выше.
3.  Разделить каждый исходный скрипт на два основных компонента: класс логики в `core/analysis/` и класс GUI в `gui/`.
4.  Заменить прямые вызовы функций на импорты из новых модулей (`core.file_io`, `core.text_processing` и т.д.).
5.  Убедиться, что каждое GUI-приложение (`gui/*_app.py`) запускается и работает идентично оригиналу.
6.  Создать точку входа `main.py` для запуска приложений.
